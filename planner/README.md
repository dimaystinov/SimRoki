# RABBIT-style trajectory planning

This is an independent five-link Lagrangian model using SimRoki's dimensions,
rectangular-link inertias, masses, damping and actuator limits. It has four internal
actuators, an unactuated stance-foot rotation, unilateral contact, friction bounds,
and an inelastic impact followed by leg relabeling. It does not copy RABBIT's
much heavier physical parameters or its optimized coefficients.

From the repository root, with Python 3.11+:

```sh
python3 -m venv .venv
.venv/bin/pip install -r planner/requirements.txt
.venv/bin/python -m unittest discover -s planner -p test_model.py -v
.venv/bin/python planner/optimize.py --step .20 --speed .30 --intervals 240 --output motions/example.json
.venv/bin/python planner/validate.py motions/example.json
.venv/bin/python planner/closed_loop.py motions/example.json --steps 40 --perturb .005
.venv/bin/python planner/poincare.py motions/example.json
cargo test --release -p sim_core --test rabbit
```

`optimize.py` uses CasADi/IPOPT and Hermite–Simpson collocation. It constrains
motor torque and relative speed, knee direction, trunk angle, hip height, swing
clearance, monotone hip progress, ground reaction, friction, endpoint position,
and periodic position/velocity after impact. `--initial` accepts a previous plan
as an optimization seed. `--clearance` controls the minimum mid-swing clearance.
The solver's constraint residual alone is insufficient: always run validation.
The output records the configuration SHA-256 and solver status.
`--constraint-margin .03` reserves 3% of motor and friction bounds to prevent
between-node interpolation overshoot in faster trajectories. The fast profile
can be reproduced with `--step .25 --speed 1 --intervals 120 --clearance .06
--lean .20 --constraint-margin .03 --initial motions/rabbit-25cm-100-high.json`.

`validate.py` independently integrates the controls using SciPy and samples
between mesh nodes. It checks dynamics residual, unilateral/friction feasibility,
foot clearance, endpoint drift and impact periodicity. Slowly moving unstable
open-loop systems can amplify interpolation errors; refine the mesh rather than
relaxing the checks. A failed run writes its diagnostic report and exits nonzero.

`closed_loop.py` adds state-phased virtual constraints and event-driven impact.
The controller derives phase from monotone horizontal hip position, not elapsed
time. It uses the four joint outputs, partial feedback linearization, saturated
motor torques and no external trunk actuator. Perturbation recovery is empirical
and is not a formal Poincare stability certificate.

The Rust implementation independently constructs the inertia matrix and bias
forces and is checked against `dynamics-fixture.json`, generated by the symbolic
Lagrangian model at a nontrivial state. The native simulator still uses Rapier's
finite rectangular contact geometry. Its actual stride and speed must be measured
separately; a point-foot optimized orbit does not guarantee identical execution.

Source derivation and primary literature: [RABBIT model](../docs/rabbit-model.md).

`poincare.py` computes a nine-dimensional post-impact return map with two finite-difference step sizes. The shipped 0.3 m/s point-foot orbit has a spectral radius near 0.818; the report records refinement error and fixed-point residual. This local numerical result does not certify the native contact model.
