# Научная рукопись о SimRoki и KNP

Автор: **Устинов Дмитрий Дмитриевич**, разработчик, заведующий лабораторией гуманоидной робототехники, АНОО «Физтех-лицей» им. П. Л. Капицы.

Версия: 11 ноября 2026 г. Это подготовленная рукопись; публикация и рецензирование не заявляются.

Репозиторий проекта: [dimaystinov/SimRoki](https://github.com/dimaystinov/SimRoki).

**[Читать статью в PDF](https://github.com/dimaystinov/SimRoki/blob/master/article/KNP_RABBIT_Ustinov_2026.pdf)** · [Исходник LaTeX](article.tex) · [Скачать архив исходников и данных](https://github.com/dimaystinov/SimRoki/raw/refs/heads/master/article/KNP_RABBIT_Ustinov_2026_sources.zip)

Статья содержит описание гибридного управления RABBIT, обучения ресурсным STDP через C++ KNP, ограничений Python bindings и парную проверку на 101 старте. В PDF приведены 17 формул, четыре рисунка, три таблицы и девять источников. Подтверждённый результат: 91 финиш вместо 69; частота первых падений пока не снизилась.

## Состав

- `article.tex` — редактируемая статья с формулами LaTeX и библиографией.
- `figures/` — четыре векторных рисунка, созданных из данных и архитектуры проекта.
- `analyze.py` — повторный анализ; не запускает роботов и не обучает сеть.
- `statistics.json` — показатели, пересчитанные скриптом.
- `paired_outcomes.csv` — удобная таблица 101 парного сравнения.
- `data/independent_audit.json` — сохранённый исходный аудит трёх вариантов; в основной статье сравниваются первые два: база G27 и r009. Третий вариант r017 не принят.
- `data/recovery_promotion_gate.json` — решение о принятии только модуля восстановления.
- `data/r009_command.json`, `data/base_command.json` — команды симулятору, включая опорные движения и карты.
- `data/r009_motion.json`, `data/r009_motion.checkpoint.json` — цели подъёма и 28 весов KNP.
- `data/resource_lean_train.cpp` — официальный KNP API в использованном учебном приложении.
- `data/knp_2.0.0_python_resource_stdp_delta.cpp` — исходный файл bindings KNP 2.0.0 с Apache-2.0 copyright/license header.
- `data/later_robust_*` — отдельный последующий опыт: учитель 6/6, KNP 4/6; не смешивается с основной панелью.
- `code/` — снимки ключевых частей реализации для проверки формул и протокола. Это не полный проект и не самостоятельная сборка SimRoki.
- `SHA256.json` — контрольные суммы приложенных данных и снимков исходного кода.

## Сборка PDF

Из каталога с `article.tex`:

```sh
tectonic article.tex
```

Либо XeLaTeX, два последовательных запуска:

```sh
xelatex article.tex
xelatex article.tex
```

Использованные шрифты: Times New Roman, Arial, Menlo, STIX Two Math. Они доступны в macOS, где выполнена сборка. Для другой системы установите эти шрифты либо замените семейства в преамбуле, выбрав шрифты с поддержкой кириллицы и математический OpenType-шрифт. Затем проверьте переносы и таблицы. Шрифты в исходный архив не включены; в готовом PDF они встроены.

Зависимости LaTeX указаны в преамбуле. Tectonic автоматически получает недостающие пакеты при первой сборке. Проверенная версия Tectonic: 0.17.0.

## Пересчёт результатов и рисунков

Нужны Python 3, NumPy и Matplotlib:

```sh
python3 analyze.py
```

Скрипт проверяет совпадение всех сценариев и полное сохранение 69 прежних успешных записей, получает 22 дополнительных финиша без потерянных финишей, пересчитывает 2000 парных bootstrap-выборок с seed 80261111. Ожидаемая нижняя односторонняя 95%-граница среднего прироста награды: **88.35256045783869**. Это исследовательская оценка по конечной валидационной панели, использованной при принятии модуля, а не внешняя статистическая гарантия.

## О границах воспроизводимости

Архив позволяет независимо пересчитать представленные статистики и пересобрать статью. Для повторного физического эксперимента нужны полный проект SimRoki, совместимая версия нативного ядра и зависимости. Старые абсолютные пути внутри журналов сохранены как часть происхождения данных; на другом компьютере их необходимо сопоставить с местоположением проекта.

`data/verified_artifacts.json` содержит контрольные суммы бинарных файлов, команды и checkpoint на момент проверки. Нативные бинарные файлы в архив статьи не включены. `robot_config.toml` скопирован из проекта при подготовке статьи; отдельный hash конфигурации в момент исходного аудита отсутствует. Команда эксперимента переопределяет общий шаг физики на 1/240 с и предел момента на 5 Н·м. Поэтому общие значения 1/120 с и 2.55 Н·м в TOML не являются параметрами основного сравнения.

## Что статья утверждает о Python и C++

В проверенных Python bindings KNP 2.0.0 присваивание `weight`, `delay` и `rule.synaptic_resource` ресурсного синапса блокировалось свойствами без setter. Рабочий контур настройки и обучения этих карт создан через C++ API и официальный CPU backend. Python остался средством организации поиска, сценариев и анализа. Это не утверждение о невозможности STDP в Python вообще, во всех версиях KNP или при изменённых bindings.

Текущий тип — `SynapticResourceSTDPDeltaSynapse`. Ранний отдельный опыт с `AdditiveSTDPDeltaSynapse` не следует выдавать за реализацию текущего ресурсного обучения. При исполнении контроллер интерполирует экспортированные веса в Rust; спайковая сеть не исполняется на каждом шаге физики.
